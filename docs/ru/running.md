# Настройка и запуск бенчмарка

[OboroLabs](../../README.ru.md) · [English](../en/running.md)

## Установить ComfyUI

OboroLabs — клиент бенчмарка. Генерация выполняется в отдельном процессе ComfyUI на той же машине или на выделенном сервере.

1. Для Mac на Apple Silicon используйте [инструкцию Comfy Desktop для macOS](https://docs.comfy.org/installation/desktop/macos) и скачайте установщик с [официальной страницы](https://comfy.org/download). Для сервера на Linux или установки из исходников следуйте [официальному руководству по ручной установке](https://docs.comfy.org/installation/manual_install) и выберите сборку PyTorch под своё оборудование.
2. Для пробного прогона скачайте [чекпойнт SD 1.5](https://huggingface.co/Comfy-Org/stable-diffusion-1.5/blob/main/v1-5-pruned-emaonly-fp16.safetensors) в папку чекпойнтов ComfyUI. При ручной установке это `ComfyUI/models/checkpoints/`. Для проверки генерации через интерфейс выберите модель в узле Load Checkpoint. [Руководство ComfyUI по генерации изображений](https://docs.comfy.org/tutorials/basic/text-to-image)
3. Запустите локальный экземпляр ComfyUI и скопируйте его базовый URL. При ручном запуске с настройками по умолчанию это `http://127.0.0.1:8188`. У Desktop или удалённого экземпляра адрес и порт могут отличаться. [Настройки сервера ComfyUI](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/cli_args.py)

## Запустить пробный бенчмарк

Установите OboroLabs [из папки проекта](../../README.ru.md#быстрый-старт). В том же терминале подставьте адрес своего ComfyUI в `COMFY_URL`.

```bash
export COMFY_URL=http://127.0.0.1:8188
oborolabs plan examples/smoke.config.json
oborolabs run examples/smoke.config.json out/smoke --server "$COMFY_URL"
oborolabs report out/smoke
```

Для прогона нужен один чекпойнт. Результат появится в `out/smoke/report/summary.md`, а изображение сохранится в `out/smoke/images/`.

## Конфигурация

1. Скопируйте [config.json](../../examples/config.json) и [workflow.api.json](../../examples/workflow.api.json) в рабочую папку. Укажите имена чекпойнтов, доступных серверу, и опишите его окружение в поле `runtime`. Если известны ревизия модели и хеш файла, запишите их в поля профиля `revision` и `sha256`. Хеш записывайте строчными буквами.
2. Используйте пример для совместимых чекпойнтов или экспортируйте свой граф ComfyUI в формате API. Плейсхолдеры `$prompt`, `$seed`, `$width`, `$height`, `$checkpoint`, `$steps` и `$filename` должны занимать значение JSON-строки целиком. Клиент подставляет seed, размеры и число шагов как числа. Узел `output_node` должен вернуть ровно один PNG, а граф и его пользовательские узлы должны поддерживать заданные параметры.
3. Используйте выделенный сервер ComfyUI со свободной очередью и стандартным кэшем узлов. Для каждого случая задавайте одинаковые промпт, seed и размеры во всех профилях. Сэмплер должен использовать подставленный seed. Укажите базовый адрес сервера в `COMFY_URL`.

## Прогоны с прогревом

```bash
oborolabs plan examples/config.json
oborolabs run examples/config.json out/sample --server "$COMFY_URL"
```

Перед замерами для каждой пары «профиль и размер» клиент один раз прогоняет граф с seed, которого нет среди тестовых случаев. Перед каждой отправкой клиент проверяет очередь и прерывает прогон, если она занята. Для каждого исследования используйте отдельный свежий сервер, чтобы контролировать состояние кэша и стороннюю нагрузку.

Задержка измеряется от отправки HTTP-запроса до подтверждения завершения опросом сервера. В этот интервал входят ожидание в очереди и запись изображения на сервере. Скачивание замеряется отдельно, а локальный PNG записывается после окончания этого замера.

## Замер на свежем процессе

Запустите новый процесс ComfyUI и дождитесь готовности API. До отправки любой другой задачи выберите один профиль и один случай и укажите `--fresh-server`. Перезапускайте процесс перед каждым таким замером.

```bash
oborolabs run examples/config.json out/sample --server "$COMFY_URL" \
  --phase cold --profile candidate --case cube --fresh-server
```

Замер начинается с отправки задачи и включает отложенную загрузку чекпойнта. Сам запуск сервера происходит до замера, а страничный кэш операционной системы может оставаться прогретым.
